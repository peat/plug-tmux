=== why-it-dies
## Why does the job die?

```
  your laptop                     the server
 ┌──────────┐      ssh      ┌──────┐    ┌─────┐
 │ terminal │ ────────────▶ │ sshd │ ─▶ │ pty │ ─▶ bash ─▶ your job
 └──────────┘               └──────┘    └─────┘
```

**pty**: pseudo-terminal. A fake terminal device from the kernel, like `/dev/pts/3`.
bash thinks it's a real terminal; sshd holds the other end. Run `tty` to see yours.

- The connection drops. sshd notices (eventually) and closes the pty.
- The kernel hangs up the terminal: SIGHUP to bash.
- bash passes SIGHUP to its jobs. Default action: terminate. Goodbye, job.

> "Hang up" is literal: it's from when your terminal was on the other end of a modem.

=== early-answers
## Early answers

- `nohup job &`: ignore SIGHUP, output to nohup.out. Survives; you can't talk to it.
- `job & disown`: bash forgets the job, so bash never passes on the SIGHUP.
- `screen` (1987): keep the pty somewhere that doesn't hang up. Reattach later.

=== tmux-arrives
## Then: tmux

- Nicholas Marriott, 2007. The prototype was called "nscr".
- He used screen, and wanted code that "was readable and could be extended"
- 1.0 in 2009. That same year OpenBSD 4.6 put it in base, replacing window(1).
- Today: tmux 3.8 (September 2026)

--- notes
window(1), if anyone asks: 4.3BSD (1986), nine windows on one terminal, ^P prefix, a C-like config
language with if/else. No detach. OpenBSD deleted it June 2009 ("RIP; ok millert"); the 4.6 notes say tmux replaced it.
Why tmux, out loud and gently: Marriott wanted a fresh, clean codebase he could read and extend, with a
simpler config and command line. (His 2009 words were blunter: "a lot of baggage". Don't read that out.)

=== the-trick
# The trick
%indent 15

## The tmux server owns the ptys and doesn't get SIGHUP'd.

```
  your laptop             the server
 ┌────────────────┐     ┌───────────────────────────────────────────────────────────┐
 │ terminal ▶ ssh │  ▶  │ sshd ▶ pty ▶ tmux client ~ tmux server ▶ pty ▶ bash ▶ job │
 └────────────────┘     └───────────────────────────────────────────────────────────┘
                     ▲    ╰───────────┬──────────╯   ╰──────────────┬─────────────╯
               disconnect   hang up: SIGHUP, exit       no SIGHUP, keeps running
```

%indent 6
- A disconnection only loses the client; you can reattach and keep on going.
- Commands are sent over a socket to the server. We'll abuse them later ...

=== tds
## tds: one session per directory

```
function tds() {
  local dir=${PWD##*/}
  local md5=$(printf '%s' "$PWD" | md5sum | cut -d ' ' -f 1)
  local session_name="${dir}-${md5:0:6}"
  tmux new -As "$session_name"
}
```

- `~/work/api` and `~/play/api` get different sessions: name plus a hash of the path
- Part of the `tmux` plugin for Oh My Zsh
--- notes
It started as `td`. Reviewer carlosala: "there's a tool out there called td. Maybe tds is a great fit." Renamed 7 minutes later.

=== tds-bug
## But wait! A bug!

$ cd ~/sites/example.com && tds      # first time: works
$ tds                                # second time: ...

```
  directory       second tds
  ───────────     ────────────────────────────
  example.com     can't find pane: com-e71c75
  a:b             can't find window: b-123456
  %x              can't find pane: %x-123456
  =y              can't find session: y-123456
```

- `tmux new -As NAME`: when NAME exists, it's looked up as a *target*

> tmux has fancy parsing rules for targets! Interesting ...

--- notes
Target syntax: `:` separates session from window, `.` window from pane.
A leading `$` `@` `%` means an id; a leading `=` means exact match.
All four errors reproduced on tmux 3.8 on this box.

=== tds-fix
## The fix

```
dir=${dir//[.:]/_}         # separators anywhere
dir=${dir/#[\$@%=]/_}      # id and exact-match markers at the start
```

- Six characters break reattaching: `.` `:` `$` `@` `%` `=`
- `#` gets format-expanded, but consistently, so it still works

> So a directory called `#{e|*:6,7}` gets a session named `42`! Very interesting ...

> Remember the directory that did multiplication? Same language.

- `#{?cond,yes,no}` conditionals, `#{==:a,b}` comparisons
- `@options` are variables. Hooks and `run -d` are loops.

## That's most of a programming language.

=== turing
## Is tmux Turing complete?

A computer needs three things:

- **memory**: `@options`, as many as you like
- **decisions**: `#{?cond,then,else}`
- **a loop**: a config file that re-sources itself with `run -b -C -d` (no shell)

Proof by construction:

- Conway's Game of Life is Turing complete (Berlekamp, Conway & Guy, 1982)
- Paul Rendell built a working Turing machine out of Life patterns (2000)
- tmux runs Life. Life runs a Turing machine. So tmux is Turing complete.

=== game-of-life
## Conway's Game of Life (1970)

- A grid of **cells**. Each cell is alive `█` or dead `·`
- Every generation, each cell counts its 8 neighbors:
  - dead, with exactly 3 alive: **born**
  - alive, with 2 or 3: **survives**
  - anything else: **dies** (lonely or crowded)
- No players, no input. Set up the grid and watch.

```
  a glider, generations 0 to 4. After four, it has moved one cell diagonally.

  ·█··   ····   ····   ····   ····
  ··█·   █·█·   ··█·   ·█··   ··█·
  ███·   ·██·   █·█·   ··██   ···█
  ····   ·█··   ·██·   ·██·   ·███
```

=== how-life-works
## Game of Life, mapped onto tmux

- **board**: one tmux option per cell. `@c_ROW_COL` is 1 (alive) or 0 (dead)
- **count**: add up the 8 neighbors with `#{e|+:a,b}`, save it in `@n_ROW_COL`
- **rule**: `#{?#{==:#{@n},3},1,#{?#{&&:#{@c},#{==:#{@n},2}},1,0}}`
  - 3 neighbors: alive. Alive with 2: stays alive. Anything else: dead.
- **one generation**: count *every* cell first, then apply the rule (step.conf)
- **loop**: step.conf ends by running itself again after a delay (`run -b -C -d`)
- **screen**: the status bar draws the board, two rows per line

=== the-screen
## The screen is the status bar

- The board is 10 rows × 32 columns
- A tmux status bar is at most 5 lines tall, so each line shows two board rows
- Each character is two cells, one above the other:

```
   board rows 0 and 1          status line 0

     ·  █  █  ·
     █  █  ·  ·        →         ▄█▀
```

- `status-format[0]` to `[4]`: five format strings reading the `@c` options
- When a step changes the options, tmux redraws the bar by itself

=== api
## tmux is an API

$ tmux send-keys -t build:1 'make test' Enter     # type into any pane
$ tmux capture-pane -p -t build:1                 # read any pane
$ tmux wait-for built                             # block until...

=== directions
## Where this goes: three directions

- **More multiplexer**: Zellij (Rust, WASM plugins, web client), Superlogical's Rex
- **Less multiplexer**: shpool, zmx, dtach, abduco. Persistence only; your WM does the splits.
- **The terminal absorbs it**: WezTerm mux domains, iTerm2 `tmux -CC`

=== rex
## Superlogical's Rex

- Mitchell Hashimoto (HashiCorp, Ghostty); company announced July 2026

- Public testing since October: macOS first, by invitation

- Fun fact: Ghostty now has more GitHub stars than tmux
